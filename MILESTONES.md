Status: `todo` · `in progress` · `blocked` · `done`

Each numbered row is **one commit** on `feature/fast-track` — the row is the review unit. See `CLAUDE.md §17` and the `git-workflow` skill. This file is updated in the same commit as the code it describes.

## Known gaps

Real problems we shipped past on purpose. Not a wishlist.

- **M7 final review: 21 minor findings deferred (2026-09-12).** The eight must-fix items were fixed on the branch; these were not. Grouped: (a) _accent discipline_ — the scroll-progress line, the header CTA and the hero CTA are three accent elements in the first viewport (§4.1 says one); (b) _scene_ — resizing across `md` disposes and rebuilds the WebGL context (`Scene.tsx` effect keyed on `animate`); `uTime` is unbounded; `parseRgba` only handles the exact token shape; `@types/three` is 0.185 against `three` 0.186; (c) _dead or duplicated code_ — `useHasHover` has no importer; `app/not-found.tsx` hand-rolls three copies of the secondary button; the `ghost` button has no `active:` state for touch; (d) _a11y and scale_ — `ShippedPanel`'s list has no accessible name and its sha uses `text-xs`, off the type scale; (e) _stale text_ — comments in `ProjectCard`, `useMediaQuery`, `Contact`, `lib/utils.ts`; "Ship Log" mentions in `DEPLOYMENT.md` and the `admin-portal` skill; `CLAUDE.md` §9 still names `--mist`, §4.6 forgets `ScrollProgress` reads page progress, §4.3 says stat figures are mono (they are not); this file's "no admin UI" gap is outdated (the portal exists). Fix as a single sweep before M5 starts.

- **The contact form writes to MongoDB but nothing reads it back.** There is no admin UI by design (§2), so a submission is invisible until someone queries the collection. See D6 — a notification path was never chosen.
- **ALL of `content/` is invented sample data.** See `content/README.md` for the per-file list. Authorised by the owner so the sections have a correct shape to build against, and to be replaced before launch. The numbers in `work.json` and `stats.json` are fabricated, and `testimonials.json` attributes invented quotes to invented people — that is the entry with the most reputational weight if it ever ships.
- **Project covers and team photos are remote Unsplash URLs.** They must become static imports from `/public` for the blur placeholder and intrinsic sizing (§7.0) — a schema change, not just a value swap. `next.config.ts` `remotePatterns` exists only to serve them and should be removed with them.
- **The hero's "Recently shipped" panel renders invented commits.** `PLACEHOLDER_COMMITS` in `components/sections/Hero.tsx`. §4.5 sanctions a mock while the GitHub route is built, but this section's entire job is being real, so it **must not reach production**. Removed by M4.4.
- **Hero copy is a draft.** Headline and subcopy in `components/sections/Hero.tsx` were written to the §8 rules but describe a team whose actual positioning has not been supplied (D2).
- **Six links on the home page point at routes that do not exist.** `/work`, `/about`, `/team`, `/careers`, `/contact` and `/schedule` all return 404 in production — the header and footer link to them, and M5 has not been built. This is now the largest SEO problem on the site: a homepage whose internal links are dead is a crawl-quality signal, and the sitemap can only honestly contain one URL. Fixing the metrics does not touch it.
- **`NEXT_PUBLIC_SITE_URL` was never set in Vercel, and the code defaulted to localhost.** The live `sitemap.xml` advertised `http://localhost:3000` and `robots.txt` pointed its Sitemap directive there, so the sitemap was unfetchable by any crawler. Fixed by resolving the origin in `lib/seo.ts` with a `VERCEL_PROJECT_PRODUCTION_URL` fallback, so it is correct on Vercel with nothing configured. **Still set `NEXT_PUBLIC_SITE_URL` when a real domain exists** — the current canonical is the `.vercel.app` hostname.
- **TTFB is network-bound and was never the problem.** It reads 0.75s at field P75 and is already GREEN. Measured against the deployment: `/` is an edge cache HIT (`x-vercel-cache: HIT`), Brotli, HTTP/2, no redirect on HTTPS, and the proxy does not run on it. The breakdown from a ~100ms-RTT client is DNS 3ms, TCP 100ms, TLS +105ms, server +105ms — two thirds of it is connection setup, which application code does not control. **There is no code change that improves it**, and it is now the floor for everything else: LCP equals FCP, and FCP cannot begin before the server responds. The one remaining lever is browser caching for REPEAT visits (`Cache-Control` is `max-age=0, must-revalidate`, so every return visit pays a revalidation round trip). Adding `stale-while-revalidate` would help returning visitors and does nothing for first views — it trades up-to-N-seconds of staleness after a deploy, and is an open decision rather than an obvious win.
- **Core Web Vitals were fixed in the lab, not yet confirmed in the field.** Field P75 on 2026-08-09 was LCP 4.47s (poor), FCP 2.37s, INP 272ms. Three root causes were found by measurement and fixed: the hero's largest text waited for hydration (LCP), 125KB of font preloads sat ahead of the 10KB stylesheet that actually blocks paint (FCP), and the blurred ambient fields re-ran a 120px blur every frame because their layers were never promoted (INP — 640ms worst interaction vs 48ms once promoted). Lab now: LCP == FCP at every CPU tier, 576ms on a 1.6Mbps link; worst interaction 48–56ms; CLS 0.0001. **TTFB (0.75s field) is untouched and is now the floor** — LCP can only be as good as FCP, and FCP starts after the server responds. Re-read the dashboard once real traffic accumulates; the original sample was ~14 loads, so P75 was 3–4 page views wide.
